# GRZ InstaDrop prototype

Independent Enforce source using Bohemia's public `DayZPlayerUtils.DebugOverrideAnimationSpeed` API. No LUGU source or assets were used. This is a prototype for faster vanilla prone transitions; it does not restore the 1.27 animation graph or guarantee the reference video's motion.

Uses the ordinary prone/recovery controls. The graph still decides which transition is played; no forced stance changes, position jumps or new hotkeys. Default v0.1.3 uses input-only compatibility mode: it does not call any animation speed override or replace a graph. Optional native transition tuning requests drop 2.0 and recovery 1.6 only when explicitly built with `--tune-native-transitions`; those numbers are not measured transition times.

Status: first rifle test build, using 6 drop and 10 recovery paths confirmed present in the supplied 8,992-entry native filename index. Standing/crouching, lowered/raised, moving drop/recovery and on-back recovery variants are included. Injured and non-rifle transitions retain native behavior. Path names identify candidate directions, but graph usage and visible motion still require in-game verification. DayZ compilation and multiplayer playback have not been tested here.

Build: `python tools/build_instadrop.py --index INDEX --preset packaging/instadrop-update/TRANSITIONS.json`. Only filenames are used; native animations are not redistributed. The index checks existence, not animation contents or graph usage.

Install: close DayZ and stop the server. Extract the prototype ZIP and run `powershell -NoProfile -ExecutionPolicy Bypass -File .\Install-InstaDrop.ps1`. It backs up prior copies and installs only the two new addons in @GRZ_Local/Addons on both sides, verifies hashes and attempts rollback if copying fails. It does not replace GRZ_Movement or alter its 1.50 setting, outfits or profiles. This unsigned development build assumes your current local-addon testing setup; signing and server signature settings are not changed.

For an in-game test, install both generated PBOs on client and server alongside the existing GRZ movement addon. Remove LUGU from both active mod lists; GRZ refuses to activate when its known patch is present. Restart both. Compare normal prone, running-to-prone, raised rifle drop/recovery, first/third person and a second player's view. Check logs for every accepted/rejected clip. Confirm weapons, collision, inputs and current running speed still behave correctly. Roll back by removing only the two new GRZ InstaDrop PBOs and restarting both.

This prototype is kept separate from the existing reskin/movement updater. Nothing has been published for this task.

Version 0.1.1: pressing a native stance-change control while a firearm is in throw-ready/charge mode cancels that preparation, then delegates to native movement. This covers dropping to prone and returning from prone to crouch/stand using ordinary controls. It does not force or teleport stances, bypass roll/action/water checks, or interrupt the actual item-release animation. Grenade/non-firearm throwing remains native. The early command hook and the stance-query hook cover both callback orders; passive stance queries do not cancel throwing. Hold/release behavior and standing during an in-progress transition still require an in-game check; this is not a guaranteed restoration of the 1.27 graph.

Version 0.1.2 follows the supplied client log: v0.1.1 and all 16 clip overrides loaded successfully on DayZ 1.30. Direct native UAStand/UACrouch/UAProne/UAStance inputs now supplement the combined controller flag, with a 250 ms intent window across callbacks. No hardcoded keyboard keys or new input declarations are used. Rate-limited input/cancellation/native-decision traces identify whether throw preparation was cancelled, which target stance was requested, and whether native rules still rejected it. No player identifiers or text input are logged. These logs do not establish why v0.1.1 failed; the new input handling still needs gameplay validation.

Version 0.1.3 is input-only by default. Keep GRZ Movement loaded; its gait speed, camera and response settings are untouched. The supplied setup has GRZ Movement and no other known movement addon. Mods that replace input callbacks without delegating to super, or implement a different throw state, may still conflict: universal compatibility is not claimed. This addon does not register or rebind native actions, create movement RPCs or override movement speed. Native collision, water/action checks and actual item release remain in control.

The supplied RPT also reports an Autorun input-preset parse error and duplicate input declarations. These are additional findings, not established causes of the stance problem. No Autorun configuration is changed by this package.

Version 0.1.4 corrects the intended mechanic: retain the G gun-lift/throw-ready pose when requesting prone, and request standing before a prone roll completes. It no longer calls CancelThrowing. It permits only two stock-rule exceptions on real firearm stance input: throw-ready -> prone (including holding the throw-mode action) and prone roll/on-back -> standing. Charge/release, dropping an item, restrictive actions, restraint, unconsciousness, weapon operations, water and non-movement commands remain blocked from these exceptions. The native stance callback's positive decisions remain untouched.

For a mid-roll standing request, the prototype calls the native PlayerCanChangeStance(...,true) check, then uses native ForceStanceUp. Whether the DayZ 1.30 graph actually interrupts the roll cannot be established here. No replacement graph is shipped, and the exact fast 1.27 motion is not guaranteed. Speed tuning is still off by default to retain GRZ Movement compatibility.

Compatibility scope: GRZ Movement does not override CanChangeStance, so this build targets that supplied setup. A mod that adds its own negative stance decision could overlap the two stock-rule exceptions; universal compatibility with arbitrary movement/stance mods is not claimed. Keep LUGU unloaded.
