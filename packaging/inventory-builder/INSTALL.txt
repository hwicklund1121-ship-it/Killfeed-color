GRZ INVENTORY SIZES

Vests, shirts/jackets, pants and belts: 10 x 10 INTERNAL cargo (100 slots).
All other clothing, including backpacks, keeps its normal cargo size.
Guns: 10 columns x 2 rows INVENTORY footprint (20 slots).

1. Stop the server and fully close DayZ.
2. Copy the generated GRZ_InventorySizes.pbo into @GRZ_Local\Addons on BOTH
   the DayZ game client and server. Use the exact same generated PBO.
3. Restart the server and game. Your existing @GRZ_Local launch line works.

The builder catalogs clothing and rifle/pistol/launcher families in installed
config.bin resources. It expands only clothing whose inherited inventory slot
is Body, Vest, Legs or Hips. Hats, footwear, gloves, masks, armbands, eyewear,
backpacks and other slots retain their original cargo, even where a modified
parent could otherwise enlarge them. Gun attachments, magazines, damage,
handling and recoil are unchanged. Clothing's outer item size is unchanged.

Replace the previous GRZ_InventorySizes.pbo with the new one; do not load a
second copy under another name. After a full restart use /grzvip inventory
(with the latest GRZ killfeed pack) to check the client patch is LOADED and
inspect the gun in your hands (or M4A1 if none) and your worn clothing sizes.
If it says NOT LOADED, the client launcher is not loading this PBO's folder.

Back up server mission storage before applying inventory-size changes. Existing
packed guns may need rearranging because a 10-wide gun fits only at column zero
inside a 10-wide clothing grid. Do not remove an expanded-storage mod while
items occupy slots outside the original inventory dimensions.

The output config.cpp and Inventory-catalog.json list the exact items patched.
The builder reads Addons and dta; it does not install or modify game files.
Use -ExtraModPaths with the PS1 for additional ENABLED mod folders containing
binarized config.bin resources. Source-only/encrypted/compressed unsupported
configs or conflicting clothing/gun class definitions cause an error instead of silently
producing partial coverage. Rebuild after adding new clothing/weapon mods or
updating game definitions. Disabled alternative mods must not be included.

This is an unsigned development PBO for the current local server with signature
checks disabled. Test cargo layout, pickup/rotation, reconnect and persistence
before using it on a live server. No DayZ runtime test was available here.
