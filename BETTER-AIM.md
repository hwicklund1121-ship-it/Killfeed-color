GRZ Better Aim v0.1.1

Replaces the custom GRZ_Quickscope and GRZ_AimControl scope experiments with a native player-type camera-shooting setup. Our settings are 250m probe distance, 0.03m probe radius and 0.85 alignment cosine (about 31.8 degrees). The supplied PKBetterAimSetup example uses 250m / 0.10m / 0.75 (about 41.4 degrees); its file is not bundled. Official 1.29 and 1.30 script defaults are 250m / 0.01m / 0.866 (about 30 degrees). This is our own modest adjustment using the public native API, not an exact 1.29 restoration.

Native initialization runs first. This addon changes only SetCameraShootParams once for each player type. It does not override camera blends, weapon raise completion, reticle movement, recoil, firing callbacks, target selection or damage callbacks. It does not use scripted damage or a second projectile. Native weapon rules still decide when camera-based shooting applies; this setting does not guarantee every scoped/hipfire shot lands on a fixed UI pixel. Projectile flight, bullet drop, penetration, dispersion and native recoil remain. The separate pre-existing GRZ_NoSway mod is retained unless you remove it.

Remove GRZ_Quickscope.pbo AND GRZ_AimControl.pbo from both installed @GRZ_Local/Addons folders. Replace GRZ_Hitscan.pbo with the supplied native-damage compatibility build: its old native-damage rejection and scripted ray damage are removed. That file name is retained so existing installs can overwrite the broken version directly. The inert compatibility method in it does not run on firing or damage. It does not provide hitscan/no-drop behavior in this repair build.

Install GRZ_BetterAim.pbo and the matching update PBOs on both client and server, preserve your custom UAVWEAPONS.pbo and generated inventory PBO, and restart both. Scope timing, scope camera motion and recoil return to native behavior after the old scope overrides are removed. Hitmarker reporting continues through the existing GRZ_Hitmarker addon after actual native damage; the damage rollback alone cannot prove the target is damageable or that every client setting is enabled.

In-game verification still required: ordinary and quickscope body/head shots on a damageable survivor BOT, actual health loss, hitmarkers and killfeed; native and custom guns; near cover and different distances; first/third person; hipfire versus scopes; sprint/reload/bolt cycling; no delayed duplicate hits. No DayZ or Enforce runtime is available here. Static native API signatures and package payloads can be checked; aiming feel and hit registration remain unverified.
